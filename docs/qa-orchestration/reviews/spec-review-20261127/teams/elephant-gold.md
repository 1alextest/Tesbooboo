## 2. Reconstructed job and plain-language paraphrase

The existing target contracts describe a QA system whose durable project knowledge, cases, tasks, attempts, evidence, human decisions and effective method assignments have native owners. External clients can participate in task/report workflows without becoming the authority for those records. FR-058 and T-408 define execution integration, while source intake and method content already have different owners. The current source also contains real integrations and a governed Skills resolver. This is an extension of an existing product, not an empty host awaiting a marketplace.

The actual job is to permit future useful contributions without losing that separation: a team might bring selected source material into project knowledge, use an independently operated executor, import a method candidate, or display/export permitted results. Each outcome has different actors, authority, inputs and consequences. A general plugin concept is useful only if it preserves those differences and supplies a demonstrably missing seam.

In plain language, C2 says: investigate the real need, reuse Tesbo's current owners, and compare established mechanisms before selecting an implementation. If a contribution is admitted later, identify its exact version, permissions, compatibility, operation and retained history. Show what is requested separately from what is effective or observed. Keep source material, inferred analysis, approved records and actual execution evidence distinct. Stop work at the real authority boundary and retain uncertainty when external effects cannot be confirmed. The document does not choose the first plugin or authorize a registry, runtime, marketplace, schema migration or active Skill.

The core model is multidimensional rather than one plugin-status enum: delivery maturity; package identity/admission; account/source binding; project enablement/configuration generation; current acting grant; requested/effective lifecycle state; observed health; operation/attempt/evidence history. Canonical 03's transition table and canonical 04's logical field table make those distinctions inspectable. A profile need not instantiate every concept: content and existing external-client paths remain legitimate alternatives.

## 3. Questions used to challenge the candidate

These questions were formed for this review, after the disclosed candidate exposure; they are not claimed as blind discoveries.

1. What valuable result does each actor need after the word “plugin” is removed, and which existing owner can already produce it?
2. Which event changes authority: installation, connection, project activation, a human decision, or a current grant? Could one be mistaken for another?
3. Can the same stored connection ID refer to a different external source later, and what happens to delayed work and historical knowledge?
4. What durable or external effect is actually prevented when the UI or run record says disconnected/failed?
5. Does withdrawing live collection also withdraw a person's right to read retained project knowledge, or are those separate policies?
6. Can an engineer identify what is settled and what must be selected later without treating illustrative field names or vendor mechanisms as deployed contracts?
7. Does an external source establish a mechanism, a limitation, an observed outcome or demonstrated efficacy, and does the proposal preserve that evidence class?
8. Would a declarative method package or existing external executor be forced into source-connector assumptions, or can no-plugin use remain valid?

Source settlement of a run is not a fence on all later native effects. | Conceptual witness: a worker loads a ticket/connection and awaits comments or analysis; owner disconnects and settles runs; worker resumes and reaches the mirror upsert under a folder lock. The retained-data counterexample is material: disconnecting a provider can validly stop live collection while a project member continues to read already imported knowledge. Candidate 03:2143 preserves that behavior and separately requires respecting an actually revoked read grant. Treating disconnect itself as a universal data-read revocation would regress the inspected owner; this review found no such remaining mandate in C2's governing text.
