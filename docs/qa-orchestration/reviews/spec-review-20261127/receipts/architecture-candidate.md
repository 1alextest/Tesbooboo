## Architecture and ownership assessment

The candidate coherently separates general extensibility from the existing execution-agent contract. FR-125 supplies the general optional-contribution outcome while FR-058/T-408 retain the narrower executor owner. T-462 is design qualification; it does not authorize a runtime, first plugin, marketplace, SDK or dependency. AC-094 preserves a single acceptance identity with individually reportable dimensions rather than inflating historical/native test counts.

The domain mapping preserves the current authoritative integration/knowledge, Task/attempt/Run, evidence, Skills and native approval owners. It expressly rejects forcing execution and reporting through the ticket-shaped integration model. Shared metadata, authentication, receipts and observability may be composed without making one contribution schema authoritative for unrelated effects.

Package/capability dependencies are distinguished from v48 work-unit dependencies and application/assurance relationships. Required/optional edge meaning, compatibility, change/revocation impact, stale-basis refusal, unaffected shared resources and historical receipts have explicit dispositions. Existing v47–48 authority, stopping, resource and uncertain-effect contracts are referenced rather than cloned into a second subsystem.

The selected-provider/default contract closes an important seam: install order and an unavailable provider do not silently select a replacement. Current/historical work retains its actual contribution/version, and a compatible admitted fallback still requires current authority and attribution. Persistence admission also accounts for meaning after a sole renderer is removed; an opaque retained blob does not become usable evidence simply because its bytes remain stored.

The proposed logical associations do not masquerade as implemented REST routes, tool names, JSON keys or schemas. Initial profile, hosting/distribution, code/UI boundary, support and migration choices remain explicit implementation-admission decisions. They block only the work that depends on them. No inappropriate new product authority, second evidence/knowledge store, mandatory desktop companion or new execution engine was found in this delta.
