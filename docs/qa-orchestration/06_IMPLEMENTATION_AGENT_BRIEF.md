## Goal and actual user workflow

The user discusses a feature with ChatGPT. ChatGPT writes an exact natural-language testing prompt through Tesbo MCP. OpenCode claims it through Tesbo MCP, then controls its own actually connected **Chrome MCP or Playwright MCP** to test a supported target, without Tesbo proxying the browser. It submits its complete original report/evidence to Tesbo MCP. ChatGPT reads full sources, proposes cases/results/**native Tesbo defect records and optional tracker text**, and can send a *linked verification/retest task* through Tesbo MCP to OpenCode; the retest creates a separate report, new analysis and revised proposal. The user often corrects the drafts, asks for retesting or rejects findings. Only the exact selected approved revisions become official.

Tesbo becomes the approved project QA repository and coordinates agent handoffs; migrating Excel is optional and specific to the DMIS pilot. OpenCode can be replaced by Claude Code, Codex, Kimi Code, Hermes or another capable runtime; permissions are configurable per instance. A Tesbo-managed Playwright/Appium runner is not required for the initial Chrome MCP pilot; other projects may use their own supported external browser, API or mobile tools. Preserve Tesbo's existing Jest/e2e/Playwright checks and optional automation reporter without introducing a new execution framework as a dependency.
