## Mandatory second-order questions and native boundaries

1. **Siblings and shared substrate.** Native case publication, model approval/candidate publication
   and KB review all need trustworthy actor kind, exact presented meaning and atomic audit. They
   have different domain consequences and retain their owners; a common status is not one lifecycle.
2. **Compression.** Extracting current-project authority from actual shared callers is earned.
   Exact review should share stable rules, not duplicate native cases, run results or knowledge.
3. **Adjacent categories.** Source, runtime reports and versioned document systems illustrate
   immutable observations versus interpretations and explicit authority; no competitor architecture
   or external platform parity is being imported. This is repository-grounded reasoning, not a web
   research claim.
4. **Platformization and option value.** Shared native transaction/principal/revision seams reduce
   repeated security mistakes. No generic execution platform, second approval engine or independent
   source-history store is justified by this repair.
5. **Prematurity.** Fix occurrence identity and actual current-authority boundaries now. A complete
   external assignment/report system requires the separate W-OWN/I3 design admission and producer
   evidence. UI labels and review receipts cannot substitute for it.
6. **Spec/code reconciliation.** Node/Nest/Next/PostgreSQL and current native files are the inspected
   implementation; canonical eight-file requirements and proposed ASER obligations are separate.
   Missing producer/runtime evidence remains open rather than being converted into source proof.
7. **Business value.** Correct attribution, preserved drafts and fewer false success claims reduce
   QA rework and improve confidence in evidence. No measured cost saving, commercial outcome or SLA
   is claimed from this review.
8. **Cross-role/channel continuity.** Human UI, MCP, native REST and selected Save meet the same
   semantic owner. A token issuer ID is not human assent; named client consent is not task assignment.
9. **Hardest opposite sibling.** A manual source-free report and a case-linked automated run can
   share storage/access machinery while owning different report/attempt semantics. Generic existing
   execution endpoints requiring a case cannot be relabeled as case-free intake.
10. **Orthogonal axes/Brand Deletion.** Remove Model Studio/Zyra/Change Packet labels: approved
    definition, immutable dispatch basis, native observation, interpretation and human publication
    still differ. That earns precise identity relations, not a new coordination authority.
11. **Participation.** Model mappings are supporting accepted relationships; native execution is
    the observation owner; UI summaries are projections. A generated case does not prove coverage,
    and an original report does not become a policy or official result by being stored.
12. **Candidate relationship completeness.** N11 exposes a missing version/occurrence edge from
    manifest case to native cycle item/execution. Retain original snapshot hash, current permissions,
    history and unknown legacy status; Green/QA/Purple must review resulting consumer semantics.
13. **Three-use and unfamiliar architecture.** Case, model and KB authority callers justify shared
    current-project authorization. A different stack still needs exact actor/scope/revision and
    transaction consequence; SQL names and Nesberry roles are examples, not universal rules. Full
