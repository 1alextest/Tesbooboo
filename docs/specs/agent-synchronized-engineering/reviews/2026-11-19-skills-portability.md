## Lessons distilled for reuse

These are applications of the retained principles, not new universal prerequisites or evidence that a candidate method is empirically superior. The precise source findings and counterevidence remain in the original receipts.

### 1. Keep accepted expectation independent of observed implementation

**Observation:** The recovered method bodies contain competing directions about whether observed behavior or an accepted requirement supplies the expected result. **Consequence:** A tester could faithfully encode a defect as the passing oracle. **Failure class:** Circular validation. **Invariant:** An acceptance judgment needs an independently accepted, applicable expectation. **Agnostic principle:** Separate what should happen from what was observed; retain disagreement and missing authority. **Reusable question:** What evidence makes this expectation authoritative independently of the thing being evaluated? **Example:** A currently approved limited-release restriction can be the correct expected behavior; an unapproved restriction observed in the UI remains a discrepancy. A commissioned characterization suite may describe observed behavior if its claim is labelled accordingly.

### 2. Bind an instruction to the operation it governs

**Observation:** A global blank-Actual/Not-Run checklist coexists with completed-execution review and restructuring modes. **Consequence:** Applying a creation default to historical work could misrepresent evidence. No destructive reset was observed. **Failure class:** Operation-scope leakage. **Invariant:** Presentation or review work cannot silently change the meaning of an earlier observation. **Agnostic principle:** Determine the operation and native lifecycle before applying defaults. **Reusable question:** Is this a new definition, a new attempt, review of an existing attempt, or a presentation/export change? **Example:** A new unattempted run can start Not Run while a completed run keeps its actor, build, timestamps and actual results during report reorganization.

### 3. Adapt conventions through the native contract

**Observation:** The source method assumes particular workbook hierarchy, roles, identifiers and enum conventions. **Consequence:** Direct copying can lose step-local expected results, overload native lifecycle fields or invent irrelevant prerequisites. **Failure class:** Representation mistaken for a universal rule. **Invariant:** The target's accepted meaning, identity and lifecycle survive adaptation. **Agnostic principle:** Keep reusable reasoning separate from the supported profile and explicit output mapping. **Reusable question:** Which conventions express a necessary guarantee, and which are only one presentation of it? **Example:** A mobile Appium project, a read-only API and source-free manual QA can use the same expectation/observation discipline while requiring different actors, interfaces and output schemas. These examples are conceptual, not empirical transfer results.

### 4. Attribute evidence at its actual grain

**Observation:** One intended All Roles case can have only one observed actor, and one execution occurrence can join to multiple mappings. **Consequence:** A broad label or multiplied join can overstate verification without another test taking place. **Failure class:** Evidence-grain inflation. **Invariant:** Claims retain the identity and scope of the underlying observation. **Agnostic principle:** Count observations separately from definitions, relationships and intended applicability. **Reusable question:** What was actually observed, for whom, on which build, and can this same occurrence appear twice in the calculation? **Example:** Two model mappings can link one genuine execution while the verified occurrence count remains one; a later genuine retry remains a distinct attempt.

### 5. Resolve authority and effects at the owner that commits them

**Observation:** At the inspected source pin, latest-saved selection, machine-origin provenance and separately committed native effects do not necessarily satisfy the proposed accepted-active, human-assent and atomic-publication contracts. **Consequence:** Correct-looking orchestration can select an ineligible revision or leave partial effects after failure. **Failure class:** Authority or transaction boundary mismatch. **Invariant:** Each protected effect is authorized against current applicable state and receives truthful durable outcome evidence. **Agnostic principle:** Extend the existing final owner and distinguish required atomic publication from legitimately separate authorized operations. **Reusable question:** Which owner can still refuse this exact effect after a wait, and what will authoritative readback show after interruption? **Example:** A candidate-case publication must preserve its mandatory case/audit/mapping unit; separately authorized external actions may instead produce explicit partial or uncertain receipts.

### 6. Qualify a method with independent transfer evidence

**Observation:** Recovered text, conceptual examples and an informed reviewer can show internal usefulness without a complete package or independent comparison. **Consequence:** A plausible refinement can be promoted on self-confirming examples. **Failure class:** Unwarranted generalization. **Invariant:** An effectiveness claim stays within the tasks and evidence that actually support it. **Agnostic principle:** Preserve fixed candidate/incumbent inputs, independent expectations and original outputs; test alternatives, no-change results and abstention on dissimilar tasks. **Reusable question:** What held-out result would refute the claimed improvement, and which effect belongs to the method rather than model, tools, data or code? **Example:** An independent reviewer can compare two methods under equal evidence and budget while preserving false positives, missed obligations and justified UNKNOWN results, instead of awarding credit because both repeat a supplied diagnosis.
