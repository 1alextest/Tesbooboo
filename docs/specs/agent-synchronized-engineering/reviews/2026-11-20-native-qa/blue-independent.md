## 1. Independent problem model

The central job is to retain what was asked, what actually happened, how it was interpreted, and what a human authorized, without making one of those records silently stand in for another. Neither a source repository nor an existing case is a universal prerequisite.

Actors are an authenticated human author/tester/reviewer/dispatcher, an external analysis client, one specifically registered executor installation, and narrowly scoped service workers. Runtime brand, human credential issuer, observed performer, selected driver and current authority are different facts. The same human may legitimately author and manually execute; a machine assertion that a human acted is not equivalent evidence. A single agent may have separately granted analysis and execution capabilities, but that does not create human assent.

The manual path begins with an applicable accepted requirement, policy, UI description, interview or authentic observation. The human can author through native Cases without a source checkout, behavior model, imported workbook, paid model allocation or automation selector. A source-free candidate generated by an assistant remains in shared staging. Human selected publication may create a native Draft; a separate native case approval makes an exact reviewed definition eligible for a new Run. Running it records actual human observation against that pinned definition. A defect association is not a verdict. Fix/retest records a new actual attempt linked to the earlier observation, without erasing the prior failure or pretending a Fixed bug passed.

The external path begins with an original natural-language question and authorized target scope, possibly with no cases. An explicit assignment binds a prompt/context revision to one executor installation. Claim is the grant of temporary execution authority, not evidence that the target was tested. That installation uses its own supported target driver and existing connectivity. A setup failure may produce an honest blocker report. The original report and evidence are retained independently of later analysis; receipt alone does not mutate Cases, Runs or Bugs. An analyst can identify contradiction or ask a focused retest, which creates a linked new dispatch/attempt and independent report. Human approval and selected native application remain distinct decisions. Unsupported optional drivers remain disabled without stopping unrelated raw task/report exchange.

Questions the system must answer include: Which instructions did this installation claim? Which scope was authorized versus actually observed? Which human actually observed or approved? What did a reviewer see? Which byte-complete sources supported a claim? What changed after a decision? Which operation was committed once? Is an old record original, reconstructed, imported or unknown? Can the user recover a lost response without duplicating work?

### Alternatives tested before new persistence

1. **Use generation tasks unchanged.** Rejected: `aiGenerate` reads a project model allocation, invokes `processZyraTask`, stores generated case payload, and the board filters brand/chat and limits to 50. A testing prompt requires independent dispatch/claim/report states and no provider purchase. A `provider='external'` label alone does not repair those readers/writers. A typed extension of the current task owner remains credible; a second unrelated task service/list is not justified.
2. **Use a native Run for every exploratory task.** Rejected for case-free intent: `executions` requires a `cycle_item` which requires a testcase; new membership additionally requires a current exact human approval. Fabricating a case or weakening admission would change legitimate native semantics. Link a Run only when there is an approved tested definition.
3. **Use `execution_automation_reports` or dormant `tesbo_report_*`.** Rejected as unchanged owners: the former requires a unique execution, while the latter models named test/spec cases and source runs, without task/revision/installation authority or immutable raw receipt semantics. Exact identifier search found these tables in migrations but no production TypeScript consumers. Their existence is not an implemented external report contract and does not justify reactivating a parallel result system.
4. **Use KB document revisions for originals.** Rejected as authority: a mutable authored knowledge document has different source, review and publication semantics. KB may hold approved contextual references or explicitly promoted knowledge; it cannot silently become the original report/attempt authority. Existing byte storage and relevant version mechanisms can be reused without copying this ownership.
5. **Use mutable `generated_payload` and its version number for all review history.** Rejected unchanged: V157 increments a current revision and protects committed save events/provenance, but native draft editing/deletion and save remove/reindex payload entries; all uncommitted candidate/rejection/analysis revisions are not represented by that number alone. Extend this one envelope with immutable revision/operation history.
6. **Use `executions.history` as-is for new attempts.** Rejected: it is imported JSON and `importRunHistory` can replace it; its provenance is not a new server-issued actual attempt ID. A properly constrained native extension is valid; creating a second generic execution store is not.
7. **Use `bug_links` as each finding.** Rejected: replacement keys by testcase/cycle and can change execution binding on the same link. Two discoveries of the same bug on separate attempts, or an unconfirmed observation with no bug, need their own grain. Preserve `bug_links` as compatibility association and add the smallest occurrence-owned semantics.
8. **Require complete T-422/graph work before any intake.** Rejected as a universal gate: governed authoring must meet its applicable method/output contract, but preserving original task intent and raw report bytes is not method-governed case publication. A disabled exact optional adapter must not block a supported manual workflow or raw observation intake.

1. Preserve native UUIDs, external IDs, case versions, approval receipts, Runs, cycle items, execution IDs, attachments, Bugs, links, task/session IDs and committed save events.
