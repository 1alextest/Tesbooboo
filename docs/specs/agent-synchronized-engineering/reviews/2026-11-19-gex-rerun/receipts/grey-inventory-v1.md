## Reading this inventory

Each J row is one material job, including its continuation to a human-observable effect. Failure variants are attached to that job rather than counted again. The status is exactly one FJCC state. `HOLDS` means that the **bounded contract simulation or explicitly named source subflow** supports the oracle, not that an implemented application passed. `FAILS` means a source-grounded incompatibility with the required journey; it is not a reproduced deployed defect. `INCONCLUSIVE` preserves missing implementation/authority evidence. All runtime behavior, authentic visual baselines, keyboard/AT usability, human comprehension and operational efficacy are unobserved.

All hypothetical fixtures are isolated conceptual data, not records created in Tesbo: projects A/B; accepted requirement R1 and successor R2; native case C1 with reviewed revision c1/c2; model M with r1/r2; run U, actual attempt a1/a2; skill S v1/v2 and assignment g1/g2; source binding b1 generation q1/q2. A row inherits its persona's knowledge and authorization limits, then supplies additional preconditions. The model runner may not teach the persona a source-only workaround. User feedback below is explicitly synthetic, not a quote from a real user.

Modes: **H** happy; **N** denied/negative/empty; **B** boundary; **M** mutation/clear/archive/delete; **R** interruption/retry/recovery; **C** contradiction; **T** trust; **L** low knowledge; **A** accessibility/context; **X** cross-channel/role; **Y** longitudinal. C/H/M risk means critical/high/medium. Crosscut matrices below define mandatory applicable variants; table traces do not claim that every Cartesian intersection was executed.
