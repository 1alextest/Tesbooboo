### GEX-G01 / SG1 — Failed requirement-link reads become successful empty state

**Severity:** Major candidate. **Category:** misleading system state; recovery/coverage gap. **Evidence level:** CODE-PROVEN local mechanism; user consequence source-grounded, no live observation. **Persona/goal:** P2 must reuse an existing case linked to a provider requirement. **Environment/initial state:** pinned frontend source; project A has a real linked C1; linked-key request rejects. **Modes:** negative, recovery, trust.

**Steps:** (1) Open Requirements with that provider. (2) Refresh linked keys. (3) Fail the linked-key read. (4) Inspect the state used by coverage/generation continuation. **Observed:** `Tesbo-Frontend/app/(app)/projects/[id]/requirements/page.tsx`, `refreshLinkedKeys` (428 onward), catches each Jira/Linear/Notion call into `{keys:[],counts:{},tasks:{}}` and writes those results to state. Failure and actual zero links become indistinguishable at this function. **Failure point:** fallback conversion before the user can interpret absence.

**Expected human outcome:** preserve unknown/unavailable or explicitly stale state; require successful authoritative lookup before treating coverage as absent. **User feedback:** “Did I lose the links, or could you not load them?” **Diagnosis:** source read failure is converted into reliable-empty data; a duplicate or wrong next step is a consequence risk, not an observed duplicate creation. Canonical03's Requirements integration repair and ASER-C06 already require this distinction.

**Reproducibility:** deterministic static branch; runtime outage fixture NOT RUN. **Owner:** frontend Requirements + provider/native case-link read owner; QA. **Recommendation:** separate loading/error/stale/success-empty and preserve project/request identity. **Regression candidate:** existing linked C1, reject each provider lookup, verify unavailable state and no confident no-coverage inference; recover and show C1; pair with genuine successful-empty control and late project-switch response. **Status:** pending independent reviewer, implementation disposition and runtime proof.

### GEX-G02 / SG2 — Bug association rewrites independent execution truth

**Severity:** Major candidate. **Category:** unintended secondary mutation; result-trust violation. **Evidence level:** CODE-PROVEN. **Persona/goal:** P1/P2 links an unrelated SIDE defect while retaining a legitimately Passed attempt. **Environment/initial state:** project-authorized Bug and execution in a writable manual/open run; original status/time/performer recorded. **Modes:** mutation, contradiction, history, alternate writer.

**Steps:** (1) Open existing Bug/execution context. (2) Add a valid association through native shared writer. (3) Read the execution after link. **Observed:** `Tesbo-Backend-Nest/src/legacy/legacy.service.ts`, `addBugLink` (9317–9334), commits association then calls `failLinkedExecutions`. That function (8257–8317) selects writable linked executions and for each non-Failed row writes `status='Failed'`, `executed_at=now()` and `executed_by=actorId`. Finalized automated runs are protected; the finding is limited to the writable path. Create-Bug also calls the mechanism. **Failure point:** treating association as evidence of failed expectation.

**Expected human outcome:** record classified direct/side/undetermined observation and association separately; only a separately authorized evidence-backed result operation changes an outcome. **User feedback:** “I found another bug; do not change the test I just passed.” **Diagnosis:** existing shared writer couples unrelated truths. FR-071–079, ASER-C03 and the native UX repair explicitly reject that coupling.

**Reproducibility:** static call/SQL chain; DB/browser reproduction NOT RUN. **Owner:** native Bug/link and execution owners; QA; Graph for result projections. **Recommendation:** remove causal status inference at the shared owner and preserve original attempt history; do not repair only the UI. **Regression candidate:** before/after status, execution time and performer unchanged after SIDE association across create/link/update entrances; independent legitimate direct correction remains possible and attributed; reports show same truth. **Status:** pending independent reviewer and implementation/runtime proof.

### GEX-G03 / SG3 — Saving a successor draft blocks the still-current model

**Reproducibility:** deterministic static checks; actual simultaneous requests NOT RUN. **Owner:** FR-117/Model Studio native revision/activation owner; Blue/QA. **Recommendation:** reconcile the one family-owned active pointer and exact current/historical dispatch contract before exposing this lifecycle. **Regression candidate:** save and approve r2 without activation, verify r1 remains current and dispatchable; explicit activation changes it once; stale pointer/current request fails without silently changing mode; prior attempts retain r1. **Status:** pending independent reviewer and native migration/runtime proof.

### GEX-G04 / SG4 — Mapping removal deletes the mapping record

### GEX-G05 / SG5 — Generated proposals create native cases before protected apply

**Severity:** Major candidate. **Category:** premature native publication; partial/ambiguous operation. **Evidence level:** CODE-PROVEN direct creation and transaction boundary; conditional orphan/duplicate consequence is a source-grounded failure hypothesis, not runtime reproduction. **Persona/goal:** P3/P2 obtains reviewable model-generated proposals, then publishes only exact human-approved operations. **Environment/initial state:** approved model revision, selected valid path digest, no generated-case mapping yet. **Modes:** mutation, negative, recovery, alternate writer.
