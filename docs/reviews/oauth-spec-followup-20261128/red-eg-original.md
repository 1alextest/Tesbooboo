The absence of an OAuth start setting does not justify a project-owned provider switch, another identity service or an environment editor. Keeping OAuth off while permitted API-token clients continue is a valid result.

These have different blocking scopes below; they are not evidence of a production exploit or of failed execution.

The existing architecture, scope/lifetime and release prerequisites remain necessary. Their explicit presence is a successful correction, not a new defect. This report does not select them, require all future OAuth work before a bounded increment, or establish that the revised method is more effective.

## RED-EG-03 — distinguish login secrets from the protocol authorization response

**Classification:** small documentation ambiguity; resolve before treating the sentence as an executable acceptance oracle. It is not a reason to redesign the issuer or a release-blocking exploit finding.

`C:docs/specs/mcp-oauth-chatgpt-connection.md:255` says to keep “passwords, OTPs, codes and tokens out of URLs/evidence.” In the same document the retained contract uses Authorization Code with PKCE (`:123`), and the pinned joined fixture expects the OAuth callback URL to contain `code` and `state` before exchange (`P:Tesbo-Backend-Nest/scripts/ci/oauth-interaction-redirect.cjs:182–186`). Literal “codes out of URLs” can therefore prohibit an existing callback representation without a selected response-mode/client-compatibility decision.

The likely intended reading is to keep login/password/OTP/session/continuation secrets out of application URLs and all secret values out of retained evidence, while preserving the approved provider/client authorization-response contract. Resolve that scope in the existing spec, including redaction of callback query values. Do not silently switch response mode, remove code-flow assertions or construe this as permission to log authorization codes. The documentation owner can clarify from existing behavior; changing client response handling would require its own compatibility evidence. **Check NOT RUN:** ordinary login never embeds login secrets in its URL, the approved callback/exchange still works, and diagnostic/evidence artifacts redact both login and authorization-code values.
