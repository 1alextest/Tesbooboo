## Source-specific lifecycle refinement within the existing D5 gate

The actual negotiated client-authentication method changes the refresh oracle. At the pinned dependency, [`defaults.js`:530–547](https://github.com/panva/node-oidc-provider/blob/d0c0cf6e0d48c89d3a084e3aaf6a0078642efd49/lib/helpers/defaults.js#L530) always rotates non-sender-constrained public `none` clients, but other chains rotate only near 70% TTL and stop rotating after one year. Tesbo's provider configuration does not override that helper. The real [`refresh_token.js`:129–160](https://github.com/panva/node-oidc-provider/blob/d0c0cf6e0d48c89d3a084e3aaf6a0078642efd49/lib/actions/grants/refresh_token.js#L129), blob `e869e46dd213fcb462d97dfc5b0ab785e741c018`, consumes and replaces the refresh credential conditionally; a repeat of an unrotated credential is not automatically evidence of replay detection failure.

This independently inspected detail reinforces **D5/spec:200, 263, 273 and OAUTH-19**, not a new documentation blocker or proven vulnerability. Before writing an HTTP concurrency expectation, the owner must settle offline lifetime, rotation/reuse/incident policy for the actual authenticated client, then the fixture must independently establish the rotation condition. Test public and selected signing-key client behavior where supported; do not transfer a `none` fixture's consume-on-every-use assumption silently. Regardless of rotation frequency, explicit family withdrawal and old-denied/new-consent separation remain required. A shorter owner-authorized pilot can defer unsupported combinations honestly; it cannot advertise unproved durable connectivity.

## Unexecuted hypotheses and bounded frontier

- **OTP double consumption:** `otp.service.ts`:48–59 selects an unused code, then 130–131 updates by ID without a `used_at IS NULL` compare-and-consume predicate. Concurrent success is a source-supported hypothesis, not a reproduced outcome. Spec:273 retains it. If OTP is selected, hold both calls at the actual pre-consume phase and independently count successful consume/session effects; one valid consume succeeds, second/replayed/expired fails, unrelated code remains usable. Fix only a confirmed necessary shared-owner gap, not a parallel OAuth OTP service.
- **Positive session-cache revocation:** `otp.service.ts`:94–127 checks cache before DB, deletes DB sessions before cache invalidation. `session-cache.service.ts`:57–70 populates a 60-second positive cache; 83–109 treats invalidation failure as nonfatal. A stale cache surviving a failure or read/delete/repopulate race could preserve a browser principal after withdrawal; it was not exercised and cache configuration was not inspected. Test actual ordering/failure at shared owners, with valid-cache and cache-disabled controls. Do not conflate withdrawal of a browser session with termination of separately authorized offline OAuth consent; spec:263 explicitly reserves that policy.
- **Deployment and external current state:** no live client metadata/account entitlement, egress/edge abuse controls, Node networking stack, replica keys, actual schema compatibility, signing/cookie rotation, backup-restore behavior, scanner findings, or deployed provider activation was independently observed. The public-metadata statement in spec:267 and #337 test-count statement in spec:242 are inherited checkpoint assertions, not this review's executed evidence. No claim of a current handshake follows.
- **Data and alternate effects:** shared scope/allowlist policy was traced, but every read tool's full downstream data/attachment/provider fetch and every lifecycle writer/cascade was not exhaustively traversed. Future tool catalog/metadata changes require fresh qualification; existing review language must not become blanket approval of those frontiers. #292/#338 delegated authority and future writes remain separately owned, outside this read-only increment.
- **Historical causality:** the retained retrospective:106–122 supports documented earlier obligations and later unclosed joins. It cannot establish an individual reviewer's motivation or that this amended method would reliably discover an undisclosed issue. Competing explanation—later topology/library selection introduced a new concrete join—remains supported alongside insufficient closure. Existing narrower tests and historical successful evidence remain valid in their own scope.
